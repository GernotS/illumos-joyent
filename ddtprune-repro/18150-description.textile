The recent explosion in memory prices made me consider to start working on this. The goal should be, in the words of Matthew Ahrens: "Dedup doesn't need to suck".

This ports OpenZFS "Fast Dedup" (feature@fast_dedup, com.klarasystems:fast_dedup) and the upstream fixes to it: "illumos-gate change 4810":https://code.illumos.org/c/illumos-gate/+/4810.

That said, this cannot be a one-man show; I definitely need reviewers and brave companions willing to test stuff.

h2. New on-disk feature, subcommands and properties

* feature@fast_dedup: flat-phys DDT entries, a dedup log in front of the DDT ZAPs, and per-table directories. Legacy DDTs keep working and can coexist with FDT tables; new tables are FDT once the feature is enabled.
* @zpool ddtprune -d <days> | -p <percent> <pool>@
* @zpool prefetch -t ddt <pool>@
* pool properties @dedup_table_quota@ and @dedup_table_size@
* @zdb@: DDT log, quota and prune accounting

h2. illumos-specific changes (not upstream)

* libzfs: @zpool ddtprune@ reports EALREADY ("a prune operation is already in progress") instead of @zpool_standard_error()@ turning it into EZFS_UNKNOWN and @abort()@.
* ztest: @ztest_ddt_repair@ removed (it relied on dedup-ditto repair, which flat entries drop); ztest now also varies the FDT log tunables to exercise log rotation and flushing.
* ZTS: @dedup_ddt_stray_class@ (hardening against upstream "issue 17528":https://github.com/openzfs/zfs/issues/17528, still open), @dedup_prune_all@, @dedup_prune_deadlock@, @dedup_prune_race@, @dedup_prune_args@, @dedup_prune_concurrent@, @dedup_prune_percentage@ and @dedup_prune_log_flush@ (DTrace in place of upstream's libzpool test program for "PR 19223":https://github.com/openzfs/zfs/pull/19223).

h2. Upstream changes not included

* "PR 15888":https://github.com/openzfs/zfs/pull/15888 - @zap_trunc()@: upstream lowers @zap_freeblk@ when a shrink frees the trailing leaves. This port frees the sibling leaf's blocks but never lowers @zap_freeblk@, so ZAP block ids are not reused and the "PR 16204":https://github.com/openzfs/zfs/pull/16204 fix cannot trigger; it is included for when @zap_trunc()@ is ported.
* "PR 14654":https://github.com/openzfs/zfs/pull/14654 - larger (32K) DDT ZAP blocks: tuning only; this port keeps 4K.
* "PR 17875":https://github.com/openzfs/zfs/pull/17875 - uncached DDT log/BRT I/O: illumos has no @DMU_UNCACHEDIO@.
* "PR 18055":https://github.com/openzfs/zfs/pull/18055 - compressed entry buffer size: fixes upstream's ABD-based ddt_zap compression, which this port does not use.
* "PR 18888":https://github.com/openzfs/zfs/pull/18888 - @ddt_zap_walk()@ cursor @_by_dnode@: saves a dnode hold per entry; no functional change.
* "PR 19029":https://github.com/openzfs/zfs/pull/19029 - @kmem_free@ size of @ddt_prune_entry_t@: allocation and free sizes already match in this port.
* "PR 17926":https://github.com/openzfs/zfs/pull/17926, "PR 18245":https://github.com/openzfs/zfs/pull/18245 - @zpool status -D -p@ and dedupused/dedupsaved properties: separate features, not part of fast dedup.

h2. Testing

* SmartOS built with 4810 PS40: @zfstest -T dedup@ 21/21 PASS.
* @dedup_prune_args@, @dedup_prune_concurrent@ and @dedup_prune_log_flush@ repeated 6x: 18/18 PASS.
* Before the prune fixes, a standalone reproducer showed: @-p 1@ pruning every entry; @-d@ overflow pruning recent entries; two prunes claiming the mark concurrently; zpool aborting on EALREADY; refcnt-2 entries pruned when the dedup log flushed during a prune (@zdb -bcc@ then aborted). All are fixed in PS40.
